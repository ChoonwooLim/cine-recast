# CineRecast 설계서

작성일 2026-11-18 · 상태: 승인됨 (2026-11-18)

## 1. 무엇을, 왜 만드는가

CineRecast는 참조 영상 하나를 받아 **숏 구성·카메라·동작·편집은 원본과 같게 두고, 지정한 인물과 배경을 바꿔 원본 이상의 품질로 다시 만드는** 도구다. Claude Code와 Codex에서 스킬로 부른다.

- 입력: 참조 영상(파일 또는 URL), 인물 교체표(원본 배역 → 새 인물 사진), 배경 교체표(원본 장면 → 배경 이미지), 필요하면 그 밖의 요소 교체표(크리처·소품 → 새 디자인 이미지).
- 출력: 원본과 컷 위치·길이·화면비가 같은 완성 영상, 원본과 나란히 놓은 비교 영상, 숏별 일치도 보고서.
- 용도: **외부 공개와 상업 이용**. 그래서 완성본에는 원본에서 복사한 화면 프레임과 오디오 샘플이 하나도 들어가지 않는다. 원본은 측정 기준과 생성 모델의 참조 입력으로만 쓴다.

기존 영상 분석 도구를 고쳐 쓰지 않고 처음부터 새로 만든다. 공개된 도구들은 판정 기준이 숏폼 영상에 맞춰져 있고, 정확한 재현에 필요한 카메라 경로·인물 마스크·깊이를 측정하지 않기 때문이다.

## 2. 목표

1. **구조 일치**: 컷 위치가 프레임 단위로 원본과 같다. 숏마다 카메라 움직임, 구도, 인물 동작과 연기, 조명 분위기, 색 보정이 원본을 따른다.
2. **인물 교체**: 사용자가 지정한 배역만 새 인물로 바뀌고, 그 인물은 모든 숏에서 같은 사람으로 보인다. 의상은 따로 지정하지 않으면 원본을 따른다.
3. **배경 교체**: 지정한 장면의 배경이 첨부 이미지로 바뀌고, 같은 장면의 숏들 사이에서 일관되며, 원본의 원근과 조명에 맞게 어울린다.
4. **지정하지 않은 것은 유지**: 교체표에 없는 요소는 원본과 같게 재현한다.
5. **원본 이상의 품질**: 원본보다 높은 해상도로 마감하고(최대 4K), 압축 흔적과 깜빡임이 없다.
6. **측정되는 일치도**: 숏마다 원본 대비 점수를 내고, 기준에 못 미치는 숏은 다시 만든다. 최종 합격 판단은 사용자가 비교 영상을 보고 한다.
7. **비용 통제**: 유료 생성 전에 예상 비용을 보여 주고 승인받는다. 프로젝트별 예산 상한을 둔다. 저해상도 초안으로 먼저 확인한 뒤 본 생성을 한다.
8. **새로 만든 소리**: 음악·효과음·대사를 원본 구조(박자, 컷과 맞는 타격점)에 맞춰 새로 만든다.

## 3. 하지 않는 것

- 장편 전체를 한 번에 자동 처리하는 것. 1단계 기준은 수십 초 분량의 클립이다.
- 웹 화면, 다른 서비스의 백엔드·프론트엔드 연동.
- 모델 학습이나 미세 조정.
- 숏폼 영상이 실사인지 AI 생성인지 판별하는 것. 이 도구는 재제작에 필요한 측정만 한다.

## 4. 해서는 안 되는 것

- **중국어 사용**: 스킬 문서, 소스 코드, 주석, 문자열, 모델 프롬프트, 파일명, 커밋 메시지 어디에도 중국어를 쓰지 않는다. 폴더 전체에서 한자 문자를 찾으면 실패하는 테스트로 강제한다.
- **다른 도구 의존**: 다른 영상 분석 도구의 코드를 가져오지 않고, 그 설치본을 호출하지 않는다.
- **승인 없는 과금**: 승인 기록이 없는 유료 호출은 실행되지 않는다.
- **원본 복사**: 완성본의 모든 프레임은 생성 또는 렌더 단계를 거쳐 나온 것이어야 한다. 원본 프레임을 그대로 넣는 것, 원본에서 오려 낸 인물이나 크리처를 합성하는 것은 금지한다. 영상 편집 모델의 출력은 허용한다. 교체할 것이 없는 숏도 다시 생성한다. 원본 오디오 샘플도 넣지 않으며, 원본 오디오는 비공개 비교 영상에만 쓸 수 있다.
- **권리 없는 초상 사용**: 교체 인물은 본인, 사용 동의를 받은 인물, 가상 인물이어야 한다. 가상 인물은 이 도구로 생성한 자료여야 하고, 실존 인물을 지칭하는 프롬프트로 인물을 생성하지 않는다.
- **비밀 정보 커밋**: 이 저장소는 공개 저장소다. 키, 개인 경로, 작업 영상은 저장소에 넣지 않는다.

## 5. 제약

- **위치**: 독립 공개 저장소 `cine-recast`. 나중에 따로 외부에 공개할 수 있도록 다른 프로젝트의 코드와 설정에 의존하지 않는다.
- **실행 환경**: Windows 11, PowerShell 7, Python 3.12 전용 가상환경, ffmpeg 8.1. 개발 장비의 GPU는 24GB급이다.
- **기준 도구**: ffmpeg, Blender, Higgsfield 영상·이미지·오디오 모델(클라우드, 유료). 이 셋만으로 모든 단계가 끝까지 돌아가야 한다.
- **선택 도구**: Nuke, DaVinci Resolve, Topaz Video AI, After Effects 같은 상용 도구는 상업 이용과 무인 실행이 가능한 라이선스가 있을 때만 선택 경로로 붙인다. 1단계에서는 쓰지 않는다. Nuke를 붙일 때는 내장 파이썬으로 자동화하고, 카메라 추적 노드는 NukeX 기능이라 대화형 라이선스가 필요하다는 점을 반영한다.
- **에이전트별 차이**: Higgsfield 연결이 없는 에이전트 환경에서는 분석·계획·검수·조립만 되고, 생성은 실행할 수 없다.
- **언어**: 코드·주석·데이터 키·모델 프롬프트는 영어, 스킬 문서와 보고서는 한국어.
- **로컬 모델**: 상업 이용을 허용하는 라이선스만 쓴다. 가중치는 해시를 고정하고 저장소 밖에 둔다.
- **작업 데이터**: 프로젝트 폴더는 저장소 밖(`%USERPROFILE%\Videos\cine-recast\<프로젝트>\`)에 둔다. 저장소에는 ffmpeg로 합성한 테스트 영상만 둔다.

## 6. 검토한 방식

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| 생성 모델 중심 | 숏마다 새 인물·배경을 입힌 기준 화면을 만들고, 원본 숏을 동작·카메라 참조로 넣어 영상 모델로 다시 생성 | 가장 빨리 끝까지 동작. 구축량 적음 | 카메라·동작 정확도가 모델에 좌우됨. 호출당 길이 제한 |
| VFX 합성 중심 | 원본에서 카메라 경로·마스크·깊이를 뽑아 배경을 Blender에서 같은 카메라로 다시 찍고 Nuke로 합성 | 카메라·타이밍이 가장 정확. 4K 이상 | 구축량이 몇 배. 연기·모션블러가 심한 숏은 카메라 추적이 자주 실패 |
| **숏별 자동 선택, 단계 구축 (채택)** | 공통 숏 분석 양식 위에서 숏마다 생성 경로를 기본으로 쓰고, 필요한 숏만 합성 경로로 넘김 | 1단계만으로 결과물이 나옴. 무거운 경로는 필요한 숏에만 씀 | 경로가 둘이라 유지할 것이 많음 |
| 기성 기능 래핑 (제외) | Higgsfield의 참조 영상 재현 기능만 호출 | 구축량 최소 | 4~30초 광고용. 숏별 제어와 일치도 측정 불가 |

사용자가 방식 선택을 맡겼고, 세 번째 방식은 작성자의 선택이다.

## 7. 정해진 설계

### 7.1 구성

```
cine-recast/
  skill/            스킬 본문과 참고 문서 (에이전트가 읽는 절차)
  src/cine_recast/  파이썬 패키지 (명령줄 도구)
  tests/            테스트와 합성 테스트 영상 생성 코드
  docs/             설계서, 구현 계획
  install.ps1       가상환경 생성, 패키지 설치, 스킬 등록
```

- **역할 분담**: 명령줄 도구는 결정적인 일(분석, 계획 파일 작성, 길이·색 맞춤, 일치도 측정, 조립)을 한다. 에이전트는 판단(배역 식별 확인, 프롬프트 작성, 결과 검수)과 클라우드 생성 실행을 한다. 도구는 API 키를 다루지 않는다. 생성 작업을 파일로 내보내고, 에이전트가 자기에게 연결된 Higgsfield로 실행한 뒤 결과 파일을 도구에 돌려준다.
- **설치**: `install.ps1`이 저장소 폴더를 편집 가능 상태로 설치하므로 저장소의 소스가 곧 실행되는 소스다. 스킬은 `skill/`을 Claude Code와 Codex의 전역 스킬 폴더에 복사해 등록한다.

### 7.2 작업 흐름

1. **가져오기**: 참조 영상을 받아 프로젝트 폴더를 만든다. 권리 확인 항목(참조 영상, 초상, 배경 이미지)에 대한 사용자 답을 프로젝트 파일에 기록한다.
2. **분석**: 화면 영역(레터박스 제외)을 먼저 확정하고, 컷을 찾고, 숏마다 **숏 시트**를 만든다.
3. **배역·장면 확정**: 원본에 나오는 인물과 장면 목록을 사용자에게 보여 주고, 교체표를 확정한다.
4. **계획**: 숏마다 경로와 모델, 입력 자료, 예상 비용을 정한다. 사용자가 승인한다.
5. **생성**: 초안(저해상도) → 검수 → 본 생성. 결과는 숏별 **테이크**로 쌓이고 덮어쓰지 않는다.
6. **맞춤**: 원본 숏과 프레임 수·프레임 속도·화면비를 맞추고, 색 보정을 원본 또는 목표 톤에 맞춘다.
7. **검수**: 테이크마다 일치도 점수를 내고, 기준 미달이면 사유와 함께 다시 만들 대상으로 표시한다.
8. **조립**: 원본 시간축에 맞춰 이어 붙이고, 비교 영상과 보고서를 만든다.

### 7.3 숏 시트 (분석의 산출물이자 모든 경로의 공통 입력)

숏마다 다음을 담는다: 시작·끝 프레임, 화면 영역, 대표 프레임, 카메라 움직임, 등장 요소 목록(인물·크리처·소품·배경 각각의 식별자, 화면 내 위치 궤적, 마스크), 인물 자세, 깊이, 조명과 색 통계, 소리의 타격점, 대사 구간(말하는 인물, 시작·끝 시각, 대사 내용, 입이 화면에 보이는지). 같은 인물과 같은 장면은 숏이 달라도 같은 식별자를 갖는다.

대사 항목은 3단계에서 쓰지만 양식에는 1단계부터 넣는다. 나중에 양식이 바뀌어 이미 분석한 프로젝트를 다시 분석하는 일을 막기 위해서다.

### 7.4 경로

- **생성 경로 (1단계)**: 두 가지 방법을 갖는다. 원본 숏을 영상 편집 모델에 넣어 지정 요소만 바꾸는 방법과, 새 기준 화면을 만든 뒤 원본을 동작 참조로 삼아 처음부터 생성하는 방법이다. 숏마다 어느 쪽을 기본으로 할지는 기준 클립 비교 결과로 정한다.
- **합성 경로 (2단계)**: 카메라 추적, 마스크, 깊이로 배경을 3D 공간에 다시 세워 같은 카메라로 렌더하고 인물·크리처 요소와 합성한다. 합성에 쓰는 요소는 새로 생성한 것이어야 하며, 원본에서 오려 낸 것은 쓰지 않는다. 배경이 카메라 움직임에 정확히 붙어야 하는 숏과, 생성 경로가 기준 점수를 넘지 못한 숏에 쓴다.
- **모델 정보**: 모델의 입력 종류·길이 제한·해상도·비용은 계획 시점에 Higgsfield 목록에서 읽어 온다. 고정된 표를 코드에 넣지 않는다.

### 7.5 일치도 측정

원본 숏과 테이크를 비교해 다음을 잰다: 컷 위치 오차(프레임), 카메라 움직임 유사도, 인물 자세 유사도, 구도(주요 요소 위치와 크기), 색과 밝기 분포, 교체 인물이 참조 사진과 같은 사람으로 보이는 정도, 교체 배경이 첨부 이미지와 일치하는 정도, 프레임 간 깜빡임. 점수는 보고서에 숏별로 싣는다.

여기에 더해 테이크마다 **원본과 거의 같은 화면 영역의 비율**을 잰다. 이 수치는 합격 기준이 아니다. 교체하지 않은 요소가 원본과 얼마나 같게 나왔는지 사용자가 보고 공개 여부를 판단하는 자료다.

### 7.6 비용 승인

- **단위**: Higgsfield 크레딧.
- **흐름**: 도구가 계획에서 묶음별 예상 크레딧을 계산한다. 사용자가 승인하면 도구가 승인 기록(시각, 승인 한도, 대상 숏)을 남긴다. 도구는 승인된 묶음의 작업만 내보낸다. 에이전트는 도구가 내보낸 작업만 실행하고, 실행할 때마다 작업 식별자와 실제 사용 크레딧을 도구에 기록한다.
- **재생성**: 승인 한도 안에서는 초안과 기준 미달 숏의 재생성을 추가 승인 없이 진행한다. 한도를 넘게 되면 멈추고 다시 승인받는다.
- **확인 방법**: "승인 기록 없는 유료 호출 0건"은 도구의 장부와 Higgsfield 사용 내역을 대조해 확인한다. 에이전트의 유료 호출 자체를 기술적으로 막는 장치는 1단계 범위 밖이다.

### 7.7 교체 자료 생성

교체할 인물, 배경, 크리처, 소품의 자료가 없으면 이미지 생성 모델로 만들어 쓴다(2026-11-18 추가).

- 요소를 지정하고 영어 설명을 주면 자료 생성 작업이 만들어진다. 한 번에 후보를 최대 네 장 받을 수 있다.
- 이미지 생성도 유료이므로 영상 생성과 같은 승인 장부를 거친다(7.6).
- 결과 이미지는 프로젝트 폴더 안에 보관하고 덮어쓰지 않는다. 명령 하나로 그 요소의 교체 자료로 등록한다.
- 가상 인물은 초상 사용 동의 항목을 "해당 없음"으로 통과시키되, 교체에 쓰는 모든 이미지가 이 프로젝트에서 생성된 자료일 때만 인정한다. 밖에서 가져온 사진에는 "예"가 필요하다.
- 원작의 고유 디자인(특정 크리처 등)을 새 디자인으로 바꿀 때도 같은 방법을 쓴다.

## 8. 만드는 사람이 정할 것

- 생성 경로의 숏 유형별 기본 방법과 기본 모델 (기준 클립 비교 결과로).
- 컷 검출, 인물 추적, 자세, 얼굴 비교, 마스크, 깊이에 쓸 라이브러리와 모델. 로컬로 돌릴지 클라우드로 돌릴지 포함. 5장의 라이선스 제약 안에서.
- 일치도 점수의 계산식과 합격 기준값 (기준 클립으로 조정).
- 합성 경로의 카메라 추적 도구. 합성 도구는 Blender가 기준이고, 선택 도구는 5장의 조건이 충족되면 추가한다.
- 패키지 내부 모듈 구성, 프로젝트 폴더 안의 파일 형식.

## 9. 알려진 위험

- **프레임 단위 일치는 보장할 수 없다.** 현재 생성 모델의 한계다. 측정하고 다시 만드는 구조로 근접시킨다.
- **크리처·복잡한 VFX 숏**은 재현이 가장 어렵고 비용이 많이 든다.
- **인물 일관성**이 숏 사이에서 흔들릴 수 있다. 검수 항목으로 잡는다.
- **원작 권리**: 화면을 전부 새로 만들어도 원작의 고유 디자인과 장면을 그대로 재현해 공개하면 원작 권리 문제가 남는다. 도구는 교체 수단과 권리 확인 기록을 제공할 뿐이고, 권리 판단은 사용자 몫이다.
- **모델 변경**: 클라우드 모델의 기능과 가격이 자주 바뀐다. 그래서 모델 정보를 계획 시점에 읽는다.
